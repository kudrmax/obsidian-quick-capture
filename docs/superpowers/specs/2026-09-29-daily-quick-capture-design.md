# Daily Quick Capture — дизайн плагина

Дата: 2026-09-29
Статус: продуктовая часть согласована, визуал проверен на прототипе (ветка `spike/screen-variants`)

## 1. Цель

Максимально быстрая запись мысли в сегодняшнюю daily note, в первую очередь с iPhone.
Открыл экран → напечатал или наговорил → отправил. Запись попадает под нужный заголовок
сегодняшней заметки в заданном формате.

Плагин: id `daily-quick-capture`, имя «Daily Quick Capture», `isDesktopOnly: false`.
Весь интерфейс на английском.

## 2. Вход

- Команда `Open quick capture`.
- Иконка на ленте (`mic`).

## 3. Экран

Полноэкранная модалка (`Modal`) поверх текущего окна. На телефоне высота экрана = высота окна
минус `--keyboard-height` (CSS-переменная, которую выставляет Obsidian на мобилке), поэтому
кнопки всегда над клавиатурой.

### 3.1. Раскладка

- По центру экрана (по вертикали и горизонтали) одна группа: заголовок-дата и содержимое.
  - Дата в формате `29 September 2026`, стиль как у заголовка заметки (`--inline-title-*`).
  - Содержимое: в текстовом режиме — поле ввода (центрированный текст, растёт по высоте вместе
    с текстом, при переполнении прокручивается); в аудиорежиме — статус, таймер `mm:ss`, волна.
  - Центр группы совпадает с центром экрана: сверху и снизу у области контента одинаковые отступы
    высотой с нижнюю панель.
- Внизу по центру ряд крупных круглых кнопок-иконок, стоят рядом (промежуток 24px).
  Главная кнопка (76px) всегда справа в ряду, второстепенные (60px) слева от неё.
  Самая левая — всегда «Close».
- Отступ снизу: `max(20px, safe-area-inset-bottom)`, при открытой клавиатуре — 12px.
- На десктопе колонка контента ограничена 640px.

### 3.2. Состояния и кнопки

| Состояние | Кнопки (слева направо) | Контент |
|---|---|---|
| Ввод, поле пустое | Close · **Record** | поле с плейсхолдером `What's on your mind?` |
| Ввод, есть текст | Close · **Send** | поле с текстом |
| Запись | Close · Pause · **Stop** (красная) | `RECORDING` (пульсирующая точка), таймер, живая волна |
| Пауза | Close · Resume · **Stop** | `PAUSED`, таймер, серая волна |
| Остановлено | Close · Discard · **Send** | `READY TO SEND`, итоговая длительность, серая волна |
| Отправка | Close (неактивна) · спиннер | текущий вид не меняется |

Режимы не смешиваются: начал печатать — кнопки записи нет; начал запись — поле исчезает.
Прослушивания перед отправкой нет.

### 3.3. Поведение

- На телефоне экран открывается без клавиатуры. Тап в любое место области контента фокусирует поле.
  На десктопе фокус в поле ставится сразу.
- Свайп вниз по экрану (вертикальное смещение ≥ 60px, преимущественно вертикальное) при открытой
  клавиатуре убирает фокус с поля — клавиатура прячется.
- Close / Escape при записи, паузе или неотправленном аудио: лист подтверждения
  `Discard recording?` с кнопками `Keep` / `Discard`. Без несохранённого аудио — закрывается сразу.
  Введённый, но не отправленный текст при закрытии теряется без подтверждения.
- После успешной отправки — по настройке `After sending`:
  - `Close the screen` (по умолчанию): экран закрывается, `Notice`: `Added to daily note`;
  - `Stay for the next entry`: экран сбрасывается в пустой ввод, тот же `Notice`.
- Волна: столбики по уровню сигнала микрофона раз в 60ms, прокручиваются справа налево.
  Если звук не доходит (далёкий микрофон), волна почти плоская — это и есть индикатор.

- Cmd+Enter (Ctrl+Enter на Windows/Linux) отправляет текст или остановленную запись.
- В поле ввода теги и ссылки (`[[…]]`, `[…](…)`) подсвечиваются в стиле редактора
  (`--tag-color`/`--tag-background`, `--link-color`): под прозрачным полем лежит слой с тем же текстом.

## 4. Автодополнение тегов и ссылок

В текстовом поле, по токену под курсором:

- `#` + символы тега → список тегов хранилища (из `getAllTags` по всем markdown-файлам),
  отсортированных по частоте, фильтр — нечёткий поиск (`prepareFuzzySearch`).
  Выбор заменяет токен на `#tag `.
- `[[` + текст → список markdown-заметок (имя файла и алиасы), нечёткий поиск.
  Выбор заменяет токен на ссылку от `app.fileManager.generateMarkdownLink(file, dailyNotePath)`
  (учитывает настройку wikilink/markdown-ссылок) и пробел после неё.
- Не более 20 подсказок. Реализация — наследник `AbstractInputSuggest`.
- Подсказки обновляются и при перемещении курсора (тап, стрелки), а не только при вводе.

## 5. Формат записи

Настройки:

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `Heading` | `""` | Текст заголовка, под который добавляется запись. Пусто — конец заметки |
| `Text prefix` | `- {{time}} ` | Префикс текстовой записи |
| `Text suffix` | `""` | Суффикс текстовой записи |
| `Audio prefix` | `- {{time}} ` | Префикс аудиозаписи |
| `Audio suffix` | `""` | Суффикс аудиозаписи (например ` #transcribe` для плагина Whisper) |
| `Embed audio` | `true` | `true` → `![[file]]`, `false` → `[[file]]` |
| `After sending` | `close` | `close` / `stay` |

Правила:

- Запись = `prefix + content + suffix`. Для текста `content` — введённый текст как есть
  (многострочный текст вставляется без изменений). Для аудио `content` — ссылка на файл, с `!`
  при `Embed audio`.
- Динамическая переменная в префиксе и суффиксе одна: `{{time}}` → время отправки `HH:mm`
  (например `23:35`). Другие `{{...}}` остаются как есть.
- Текст, состоящий только из пробелов, отправить нельзя (кнопка остаётся Record).

## 6. Куда вставляется запись

1. Сегодняшняя daily note определяется по настройкам core-плагина Daily notes: папка, формат
   имени (moment), шаблон. Если плагин выключен — те же значения по умолчанию, что у Obsidian
   (`YYYY-MM-DD`, корень хранилища, без шаблона).
2. Если заметки нет — она создаётся (папки тоже). Если задан шаблон — его содержимое с заменой
   `{{date}}`, `{{time}}`, `{{title}}` и `{{date:FORMAT}}` / `{{time:FORMAT}}`, как у core-плагина.
3. Поиск заголовка: первый markdown-заголовок любого уровня, текст которого совпадает с `Heading`
   без учёта регистра и крайних пробелов. Строки внутри frontmatter и внутри блоков кода ``` не
   считаются заголовками.
4. Секция заголовка: от строки заголовка до следующего заголовка того же или более высокого уровня
   (или до конца файла). Запись вставляется сразу после последней непустой строки секции
   (если секция пустая — сразу после строки заголовка). Пустые строки перед следующим заголовком
   сохраняются.
5. `Heading` пуст → запись добавляется в конец заметки на новой строке.
   Заголовок не найден → в конец заметки добавляется заголовок (через пустую строку, если перед ним
   текст), запись — сразу под ним. Уровень берётся из решёток в настройке (`### Дневник` → `###`),
   без решёток — `##`. Поиск существующего заголовка идёт по тексту, уровень в настройке не важен.
6. Правка делается через `vault.process` (атомарно относительно других правок файла).

## 7. Аудио

- Запись через `MediaRecorder` на потоке `getUserMedia({ audio: true })`.
  Формат: первый поддерживаемый из `audio/mp4` (`.m4a`), `audio/webm;codecs=opus` (`.webm`),
  `audio/ogg` (`.ogg`). На iOS и десктопе это `.m4a`.
- Запись короче 0,5 с считается пустой: ничего не сохраняется, `Notice`: `Recording is empty`,
  экран возвращается во ввод.
- Пауза и продолжение — `MediaRecorder.pause()` / `resume()`.
- Уровень для волны — `AnalyserNode` на том же потоке.
- Имя файла: `Recording YYYYMMDDHHmmss.<ext>` (как у встроенного рекордера).
- Путь: `app.fileManager.getAvailablePathForAttachment(name, dailyNotePath)` — папка вложений
  из настроек Obsidian; сохранение `vault.createBinary`.
- Микрофон освобождается при остановке, отмене и закрытии экрана.

## 8. Ошибки

- Нет доступа к микрофону или нет `MediaRecorder` → `Notice`: `Microphone is not available: <причина>`,
  экран остаётся во вводе.
- Ошибка создания заметки или записи в неё → `Notice`: `Could not add to daily note: <причина>`.
  Текст остаётся в поле, аудио — в памяти (состояние «Остановлено»), можно отправить повторно.
- Если аудиофайл уже сохранён, а вставка в заметку упала, файл отправляется в корзину
  (`fileManager.trashFile`), чтобы повторная отправка не оставляла дублей.
- Двойная отправка невозможна: на время отправки кнопки неактивны.

## 9. Архитектура

```
src/
  domain/          чистая логика, без Obsidian API
    EntryFormatter.ts       prefix + content + suffix, {{time}}
    SectionInserter.ts      вставка записи в текст заметки
    CaptureToken.ts         токен #tag / [[link под курсором
    Clock.ts                интерфейс времени
  application/
    CaptureService.ts       captureText / captureAudio через порты
    ports.ts                DailyNoteGateway, NoteWriter, AttachmentStore
  infrastructure/          реализации портов на Obsidian API
    ObsidianDailyNotes.ts   настройки Daily notes, создание заметки по шаблону
    ObsidianNoteWriter.ts   vault.process
    ObsidianAttachments.ts  getAvailablePathForAttachment, createBinary, generateMarkdownLink, trashFile
    MediaAudioRecorder.ts   MediaRecorder + AnalyserNode
  ui/
    CaptureModal.ts, CaptureScreen.ts, Waveform.ts, CaptureSuggest.ts, SettingsTab.ts
  settings.ts
  main.ts
tests/                     vitest: domain и CaptureService с фейковыми портами
```

UI зависит только от `CaptureService`, `AudioRecorder`-интерфейса и настроек; domain не знает про
Obsidian. Визуал и машина состояний экрана переносятся из прототипа.

## 10. Тестирование

- Юнит-тесты (vitest): `EntryFormatter`, `SectionInserter` (заголовок разных уровней, регистр,
  пустая секция, секция до конца файла, заголовок во frontmatter и в блоке кода, заголовок не найден,
  пустой `Heading`, файл без завершающего перевода строки, многострочная запись), `CaptureToken`,
  `CaptureService` с фейковыми портами (создание заметки, откат аудиофайла при ошибке).
- Ручная проверка на десктопе (через Obsidian CLI) и на iPhone: текст, аудио с паузой,
  отсутствие заголовка, отсутствие заметки, автодополнение, свайп, закрытие с подтверждением.

## 11. Не делаем

- Прослушивание перед отправкой.
- Динамические переменные кроме `{{time}}`.
- Отдельную настройку тега для аудио (делается суффиксом).
- Запись в заметку за другой день.
- Подсказки сторонних плагинов в поле ввода.

## 12. Развёртывание

Сборка кладёт `main.js`, `manifest.json`, `styles.css` в `~/Obsidian/.obsidian/plugins/daily-quick-capture/`
(синхронизируется на телефон через Obsidian Sync). Прототип `daily-quick-capture-spike` после
установки основного плагина выключается и отправляется в корзину.

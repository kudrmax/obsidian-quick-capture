# Quick Capture — режимы, уровень заголовка, переименование

Дата: 2026-09-29
Статус: продуктовая часть согласована в чате
Базовая спека: `2026-09-29-daily-quick-capture-design.md` (всё, что здесь не сказано, работает как там)

## 1. Цель

Плагин перестаёт быть только про daily. Запись идёт в один из **режимов**: например, мысли —
в daily, заметки по книге — в файл книги. Принцип «сначала пишу, потом решаю куда»: смена режима
никогда не теряет введённый текст или голосовое.

## 2. Переименование

- Плагин: id `quick-capture`, имя «Quick Capture». Описание:
  «Fullscreen quick capture of text and voice into your daily note or any note.»
- Пакет npm `obsidian-quick-capture`, класс плагина `QuickCapturePlugin`. Папку репозитория не трогаем.
- Деплой в `~/Obsidian/.obsidian/plugins/quick-capture/`. Текущий `data.json` переносится туда
  (миграция его формата — п. 6), старая папка `daily-quick-capture` отправляется в корзину через `trash`.
  Плагин включается заново (на телефоне — вручную, один раз).

## 3. Настройки

### 3.1. Общие (по умолчанию для всех режимов)

| Поле | Что это |
|---|---|
| Heading | Текст заголовка без `#`. Пусто — запись в конец заметки |
| Heading level | Выпадающий список H1–H6, по умолчанию H2. Используется, когда заголовок создаётся |
| Text prefix / suffix | Как сейчас |
| Audio prefix / suffix | Как сейчас |
| Embed audio | Только глобально |
| After sending | Только глобально |
| Quick tags | Группы тегов, как сейчас (у группы появляется скрытый стабильный `id`) |

Если в поле Heading всё же написано `### Дневник`, решётки задают уровень, как раньше (обратная совместимость).

### 3.2. Режим

| Поле | Что это |
|---|---|
| Title | Заголовок экрана записи — он же название режима в списке и в команде. У `Daily note` можно оставить пустым: тогда заголовок — сегодняшняя дата (`29 September 2026`), как сейчас |
| Type | `Daily note` или `File` |
| File | Только для `File`: путь к `.md`, выбор с подсказками по заметкам хранилища |
| Heading, Heading level, Text/Audio prefix/suffix | Переопределения общих. Пустое поле = наследовать; общее значение показано серым плейсхолдером |
| Tag groups | Переключатель на каждую группу. В режиме видны только включённые группы |

- Heading level в режиме: `Default` (наследовать), H1–H6 и `No heading` — запись в конец файла
  (иначе пустой Heading режима нельзя было бы отличить от «наследовать»).
- Пустые префикс/суффикс в режиме означают «наследовать»; переопределить на пустую строку нельзя
  (осознанное упрощение).
- Режимов сколько угодно, минимум один: у последнего режима кнопки удаления нет.
- Порядок режимов = порядок в настройках = порядок в списке на экране.

## 4. Запись в заметку

- **Daily note** — как сейчас: сегодняшняя daily, создаётся по настройкам Daily notes.
- **File** — выбранный файл. Если его нет, создаётся (вместе с папками) пустым. Если путь пустой
  или указывает не на `.md` — ошибка «Choose a file for mode "<title>"», запись не пропадает.
- Аудиофайл сохраняется во вложения относительно целевой заметки, как сейчас.
- Файл режима определяется **в момент отправки**, не при открытии экрана.

### 4.1. Пустая строка после заголовка

Меняются только вставляемые строки, существующий текст не трогаем:

- Заголовок создаётся (его нет в заметке или заметка пустая): `### Дневник`, пустая строка, запись.
- Заголовок есть, секция под ним пустая: если сразу после заголовка уже стоит пустая строка — запись
  идёт после неё; иначе вставляется пустая строка и запись.
- В секции уже есть записи — новая идёт после последней непустой строки, как сейчас.

## 5. Экран записи

### 5.1. Заголовок = режим

- Отдельной плашки нет: заголовок экрана и есть режим. Daily без своего заголовка показывает дату.
- Если режимов больше одного, справа от заголовка маленький серый шеврон `▾` (на той же строке),
  по нажатию — лёгкая подсветка. При одном режиме шеврона нет, заголовок не нажимается.
- Тап по заголовку — под ним список заголовков режимов (текущий отмечен ✓, шеврон повёрнут вверх),
  введённый текст приглушается (серый, не скрыт). Тап по режиму — выбран, список закрыт, заголовок сменился.
  Тап мимо — закрыть без изменений.
- Слой тегов и список режимов взаимоисключающие. Close / Esc сначала закрывает открытый слой.
- Утверждено по макету `modes.html`, вариант 1 «Шеврон рядом».

### 5.2. Сохранность записи при смене режима

- Текст в поле остаётся как есть.
- Аудио: запись продолжается / пауза остаётся / остановленная запись остаётся готовой к отправке.
- Выбранные теги, которых нет в группах нового режима, снимаются; остальные остаются.
- Кнопка `#` показывается, только если у режима есть включённые группы с тегами.

### 5.3. Какой режим открывается

- Команда `Open quick capture` и иконка на ленте открывают **последний использованный** режим
  (запоминается при выборе в заголовке, сохраняется в настройках). Если его удалили — первый режим.
- Для каждого режима команда `Capture to <title>` (Daily без заголовка — `Capture to daily note`) — открывает экран сразу в этом режиме
  (для ярлыков iOS). Команды обновляются при изменении списка режимов.

## 6. Миграция старых настроек

Старый формат (нет поля `modes`):

- `heading`, префиксы и суффиксы → общие настройки. Если `heading` вида `### Дневник` —
  heading `Дневник`, level H3; без решёток — level H2 (как вело себя раньше).
- Группам тегов выдаются `id`.
- Создаётся один режим типа Daily note с пустым Title (заголовок — дата), без переопределений, все группы включены,
  он же последний использованный.
- `embedAudio`, `afterSend` остаются глобальными.

## 7. Архитектура

- **Domain:** `CaptureMode`, `EntryFormat` (heading, level, префиксы/суффиксы) и чистая функция
  разрешения формата режима поверх общих настроек; `SectionInserter` учится вставлять пустую строку
  и принимает уровень заголовка отдельно; миграция настроек — чистая функция с тестами.
- **Application:** `CaptureService.captureText/captureAudio` принимают режим. Цель записи
  определяется портом `NoteTargets.resolve(target)`: daily — существующий gateway, file — новый
  `ObsidianFileNotes.getOrCreate(path)`.
- **UI:** `ModePicker` (по образцу `TagPicker`), заголовок-переключатель в `CaptureScreen`, секция Modes в
  `SettingsTab`, `FileSuggest` для пути. Автодополнение ссылок считает путь от заметки текущего режима.

## 8. Тесты

TDD, vitest: миграция, наследование полей, выбор групп тегов по режиму, пустая строка после
заголовка (все случаи п. 4.1), запись в File-режим (существующий и новый файл, пустой путь),
fallback на первый режим при удалённом последнем, снятие тегов при смене режима.

## 9. Не делаем

- Другие типы режимов (weekly, новая заметка на каждую запись и т.п.).
- Переопределение Embed audio и After sending в режиме.
- Динамические переменные кроме `{{time}}`.

# Quick Capture — несколько файлов в режиме, алиасы

Дата: 2026-09-30
Статус: согласовано в чате
Базовая спека: `2026-09-29-capture-modes-design.md` (всё, что здесь не сказано, работает как там)

## 1. Зачем

Сценарий «книги»: формат записи один (заголовок, префиксы, теги), а книг несколько, читаются
параллельно, часто меняются и лежат в разных папках. Имена файлов длинные. Заводить режим на каждую
книгу неудобно, настройки бесконечно растут.

## 2. Модель

- Режим задаёт **формат** (переопределения, группы тегов) и **куда писать**.
- Тип режима: `Daily note` (как было) или `Files` — список файлов. Режим с одним файлом —
  это `Files` со списком из одной строки, отдельного типа «File» больше нет.
- Файл режима: `alias`, `path`, время последней записи в него. Алиас необязателен.
- **Место записи** (destination) — пара «режим + файл» (для Daily — сам режим). Экран записи,
  список на экране, команды и «последний использованный» работают с местами записи.

## 3. Настройки

- Название режима:
  - `Daily note` — заголовок экрана, как было (пусто — сегодняшняя дата).
  - `Files` — только имя группы в настройках (например «Книги»), на экран не выводится.
- `Writes to`: `Daily note` / `Files`.
- Для `Files` — строки `[алиас] [файл с подсказками] [🗑]` и кнопка `Add file`.
  Удаление строки файл заметки не трогает.
- Формат и группы тегов — как было, общие для всех файлов режима.

## 4. Экран записи

- Список мест записи **плоский**, те же капсулы. Порядок: режимы в порядке настроек, внутри режима
  файлы по последней записи в них (свежие сверху; ни разу не использованные — в порядке настроек, после использованных).
- Название места: у файла — алиас, если пусто — имя файла без `.md`; у Daily — как было.
- Заголовок экрана — название текущего места; шеврон, если мест больше одного.
- Файлы с пустым путём или не `.md` в список не попадают. Если мест нет совсем — экран не открывается,
  уведомление «Add a file in Quick Capture settings».
- Открывается последнее выбранное место (как раньше с режимом); если его удалили — первое.
- «Последняя запись» в файл обновляется после успешной отправки.

## 5. Команды

`Capture to <название места>` на каждое место (Daily без заголовка — `Capture to daily note`).
Id команды — `capture-<id места>`.

## 6. Миграция

- Режим старого типа `File` (путь `P`, заголовок `T`) → `Files` с одной строкой: алиас `T`, путь `P`,
  **id строки = id режима**, чтобы id команды (`capture-<id>`) и последний выбранный режим сохранились.
  Название режима остаётся `T`.
- `lastModeId` → `lastDestinationId` с тем же значением.

## 7. Архитектура

- **Domain** (`CaptureMode.ts`): `NoteTarget` (daily | file с путём), `ModeFile`, `Destination`,
  чистые `listDestinations`, `pickDestination`, `markUsed`. `resolveFormat`, `modeTagGroups`,
  `retainTags` — без изменений.
- **Application:** `CaptureService.captureText/captureAudio(destination, …)`; `NoteTargets.resolve(NoteTarget)`.
- **UI:** `ModePicker` показывает места; `CaptureScreen` работает с местом; `SettingsTab` — строки файлов.
- **main:** команды по местам, `onCaptured` обновляет «последнюю запись».

## 8. Тесты

TDD, vitest: миграция `File` → `Files` (id, алиас, lastDestinationId), плоский порядок и сортировка
по последней записи, название места (алиас / имя файла / дата), пропуск пустых путей, fallback
на первое место, запись в файл места, `markUsed`.
